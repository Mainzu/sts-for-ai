# Searching any-number picks (Purity): four designs and three judges (2026-11-13)

Design review for `docs/specs/draw-knowledge.md` item 6. Problem: kb `measurement/purity-search-cost`.
Four readers each designed from one angle (structure, budgeting, decomposition, learned prior); three judges
scored all four through one lens each (soundness, generality, engineering). Scores 1-5, 5 best; cost 5 = cheapest.

## Canonical-order pick walk with resolved-outcome beam screening (the pick becomes one macro decision)

Today a pick runs in Tree::expand as ordinary Decision nodes. Each Choose(c) and Done becomes an edge, and the memo merges orderings because they reach equal states. So each start of Purity's pick creates one node for every sub-multiset reached so far, plus one for every resolved outcome, and every resolved outcome is then searched to the end of the turn. The design changes how a pick is expanded in three layers. All of them apply only the engine's existing actions (apply_action with Choose/Done), so state.rs stays the one source of truth.

(1) Canonical walk. When expand reaches a state where a pick has just started (s.pick() is Some and the parent was not in a pick), it does not make nodes for the intermediate pick states. It walks the pick as a binary decision diagram over the distinct candidate card ids, in a fixed order (CardId ascending). At each level it decides how many copies of that id to take, from 0 up to min(count, left), by applying that many Choose(id) actions. A prefix of decisions is finished by applying Done when the pick is not exact; this is legal and gives a fully resolved, card-boundary state, called the prefix's completion. The walk is used only for pick kinds whose result does not depend on order: ExhaustFromHand, DiscardFromHand, UpgradeFromHand, ReturnFromDiscard, ReturnFromExhaust, and Offered with n=1. A new state.rs fn PickKind::order_free() marks these. HandToTop and DiscardToTop write the `top` order, so for them the walk runs over sequences (the per-level choice is which card goes next) instead of counts. There is a runtime guard: if any Choose in the walk leaves a pending chance event (for example a Dark Embrace draw) or a stage other than "same pick continues / card resumes", the walk is abandoned and that pick is expanded sequentially, exactly as today. The walk's results are the distinct resolved afterstates, merged by state equality through the existing leaf_index/memo. Each result is stored as a child of a new node kind, Node::PickSet(Vec<(seq_id, child)>), and the Choose/Done action sequence that reached each child goes in a side table, so the line can still be replayed.

(2) Screening after the card resolves. If a pick has at most T resolved outcomes (default T = K = 8), every outcome is expanded, and the result is exact and identical to today's search. Above T, the pick is screened by a beam over the decision diagram's levels. At each level, every surviving prefix branches into its count choices. The completion of each new prefix is scored by the evaluator. That is allowed because a completion is a fully resolved state, never half of a card. The best B prefixes are kept (B = K). After the last level, the K best complete outcomes are expanded normally (the cap still applies at card boundaries). The other outcomes that were scored become ordinary evaluator leaves, with the values they already have. The "pick nothing" completion (Done at once) is always kept, as a deterministic anchor. Exact picks have no Done-completion; when one has more than T outcomes, all of its outcomes are enumerated and the K best are kept (the same screening, without the beam).

(3) Phased build, so the evaluator gets large batches. search() builds in rounds. Round 0 builds the tree as now, but each oversized pick start is recorded as pending and given a placeholder. Then the beam advances all pending picks together, one level at a time, with one eval.evaluate call per level across every pick (about 10 batches, not about 6,000 small ones). A HashMap from leaf index to value caches every scored state, so a state is never scored twice, and the final leaf pass reuses these values. Next the chosen outcomes are expanded. Any new oversized picks they reach go into the next round (this loop ends because picks only occur within the turn's finite card plays). Last, the remaining leaves are scored and values are backed up as today, with PickSet nodes backed up as a max. Ties are ordered by (value descending, canonical prefix order), so the search is deterministic.

**Exactness.** Exact: the canonical walk on its own (layer 1, with K = infinity). An order-free pick reaches the same set of resolved afterstates as the sequential Choose expansion, merged by state equality as concept.md requires. So the search value and the root choice equal today's uncapped search. A test asserts this on the Purity+ hand and on random pick states. A second test compares canonical-order and reversed-order application for each order_free kind, so a future trigger that breaks order-freedom fails a test and is not silently accepted. The evaluator never sees a half-resolved card: completions and outcomes are all past Done. Approximate: screening (layer 2) is a beam. An outcome is left unexpanded if its own evaluator value (before the rest of the turn is played) ranks low, even when its continuation would be best. Failure cases: (a) exhausting a card the rest of the turn needs gone (for example clearing the hand before a hand-size-dependent card such as Second Wind or Fiend Fire, or before draw that would hit the 10-card limit) looks bad as a completion but is best after continuing; (b) the beam is greedy over levels in card-id order, so a pair of cards that is only good when exhausted together can be dropped at the first level; (c) the quality of a mid-turn evaluator value (as with today's cap cuts). K = infinity, or a pick with at most T outcomes, restores exactness, so small picks (Headbutt, Warcry, Armaments, Exhume) are unchanged. If the guard abandons the walk (chance mid-pick), that pick falls back to today's exact sequential expansion. Order-free kinds with order-dependent deterministic triggers would be wrong; the reversed-order test is the safeguard.

**Cost estimate.** Measured baseline: 300,645 nodes uncapped, 617 pick starts, up to 638 sub-multisets each, 34,867 distinct end states. Layer 1 alone removes the intermediate pick-state nodes and the about 5x Choose edges per subset. That is roughly the half of the 300k that are partial-pick states, so about 150k nodes, still exact. With layers 2 and 3 at K = B = 8, T = 8: each pick start keeps at most 8 outcomes, so there are at most about 5,000 expanded outcomes (617 x 8). The 407 starts at 0 energy continue only to EndTurn, Anger, and so on (a few nodes each). The 5 starts at 3 energy and the 42 at 2 energy carry most of the continuation, about 8 outcomes times a sub-turn of a few hundred nodes. Estimate: 20k to 35k tree nodes, close to the no-pick baseline of 14,623 plus the Purity branches, and well under the 50,000 cap, so 0 cuts compared with 957 now. Screening adds evaluator states: per start at most about L x B x (choices per level) completions, about 9 levels x 8 x 2 = about 150. Merging equal completions across starts cuts this sharply (equal hands after equal plays give equal completions), so I expect 30k to 60k screened states before the merge and about 15k to 30k distinct after it. These go out in about 10 large batches. Leaf evaluations total about 20k to 40k, compared with about 35k today when uncapped. The risk is that net evaluation is slower per state than expanding a node; the probe below measures wall time, not only node count.

**Engine changes.** engine/src/search.rs (L): Node::PickSet plus a side table of action sequences (any line or principal-variation extraction replays the sequence); Tree gets an evaluator reference or a pending-picks list, a value cache keyed by leaf index, and the round loop in search(); a new Tree::walk_pick (canonical diagram walk, completion via Done, guard fallback to the current sequential branch); the beam in a level-synchronous screen_round; SearchConfig gets pick_keep: K (0 = exact/off, default 8) and pick_exact_upto: T. Back-up and tie keys handle PickSet like Decision. engine/src/state.rs (S): PickKind::order_free(), and nothing else, because the walk goes through apply_action/legal_actions; at most a small pub helper that lists pick candidates with their counts (pick_source already exists). Tests (M): exactness test with K=inf against the current search on the Purity+ hand and on Gambler's Brew/Warcry/Headbutt states; an order-freedom test for each order_free kind (canonical vs reversed order equal); a determinism test (two runs give identical trees). Python bindings: expose pick_keep in the search config (S). No changes to content or wording, since no new content element is added.

**Measurement.** Probe (reusing the purity-search-cost setup: the 10-card Purity+ hand vs Jaw Worm, plus the same hand with a no-pick card): record nodes, cuts, distinct end states, screened states, evaluator states, number of evaluate batches and wall time, for K in {4, 8, 16, inf}, with both the heuristic and the net. Checks: K=inf gives the same root values and choice as today's uncapped search (exact); nodes at K=8 are under 50k with 0 cuts; regret = (exact uncapped value of the best root option) minus (exact uncapped value of the option chosen at K), averaged over about 200 sampled turn states from Purity, Gambler's Brew, True Grit+, Burning Pact, Warcry and Headbutt decks. A second number is how often the K-screened pick choice matches the exact best pick. Play quality: a paired sweep (same seeds) on decks with an any-number pick card, comparing current cap-50k against K=8 and K=16 at equal wall time, reading win rate and final HP, run as a pinned job. The design is accepted if K=8 has regret near 0 on most states, does not lose win rate or HP, and makes the Purity turn at least 5x cheaper in wall time than the uncapped search.

## Pick ration: enumerate each large pick's outcomes off-tree, keep the best k by a static rank, and build one path per kept outcome

I read engine/src/search.rs (Tree::expand, child, the memo and Index) and the pick code in state.rs (Pick{kind,left,exact,free}, legal_actions at a pick, the Choose/Done branches of apply_action, pick_source).

The idea is to treat a pick as a separate subproblem that is solved off the tree before the tree grows into it.

1. Spotting the start of a pick. In Tree::expand, a state with s.pick().is_some() that is not part of the active pick plan (see 4) is the start of a pick.

2. Listing the outcomes off the tree. From the start state, run a breadth-first walk that goes only through pick states: clone the state and apply_action for every legal Choose or Done. It keeps its own afterstate dedup, using the existing Index over a local Vec<CombatState>, and it creates no tree nodes. A state where pick() is None (the card has run on to the next decision or chance node, or the fight is over) is an outcome (pick exit). For each distinct exit it records the action path that first reached it, in breadth-first order, so smaller choices are found first. The walk stops at cfg.pick_states internal states (default 4096). Because the walk is breadth-first and its order is fixed, a stopped walk keeps the shallow exits and drops the deepest ones, the same way on every run.

3. Choosing which outcomes to keep. If the pick has at most cfg.pick_exact distinct exits (default 12), nothing changes: expand the pick exactly as today, with no plan, so single-card picks (Armaments, Headbutt, Warcry, Offered) give identical trees. Otherwise, rank the exits by a cheap static value: heuristic::estimate, called directly and never through the configured evaluator. Every exit is a fully resolved card (the pick is finished and the card has run on), so nothing half-resolved is ever scored. Then keep:
- the "take nothing" exit (Done at the first step), when the pick is not exact;
- the cfg.pick_keep best exits by rank (default 6). Ties are broken by breadth-first order, which keeps the result deterministic.

4. Keeping one path per kept outcome. The plan is the set of internal states on the recorded path of each kept exit (at most pick_keep+1 paths, each with at most n steps), plus the kept exit states themselves. It goes onto a plan stack in Tree. While a plan is on top of the stack, the Decision branch of expand drops any Choose or Done child whose afterstate is not in the plan. A child that leaves the pick must be a kept exit. The plan is popped when the expand call for the start state returns. A new pick that begins inside a kept exit's continuation is not in the top plan, so it pushes its own plan. That covers nested picks and later pick cards.

5. Everything else stays as it is. The tree keeps its node shapes (Decision and Choose actions), so the principal line, root option merging, OptionScore and tie keys need no changes. Picks stay exempt from max_nodes, which is now safe because a planned pick adds at most (pick_keep+1)*n internal nodes. The cap still cuts at card boundaries. Order-free and ordered picks are handled the same way, because exits are deduplicated by afterstate (docs/concept.md). Choosing A then B and choosing B then A merge only if the engine says they reach the same state.

With a generous budget (pick_keep >= the number of exits and pick_states never reached) every exit is kept. Then max over the pruned subtree equals max over the full subtree, because each exit's continuation is expanded in full, so the result is exact (only the internal node count differs). pick_keep = 0 turns the feature off.

**Exactness.** What stays exact:
- Every pick with at most pick_exact (12) distinct outcomes, which covers all single-card picks and all "pick 1 of up to 12": the code path is identical to today's, with byte-identical trees and results.
- Every kept outcome: its continuation is searched exactly as today, under the same max_nodes rule and the same evaluator.
- The "take nothing" outcome of a non-exact pick is always kept, so a budgeted Purity can never score below "play Purity, exhaust nothing".
- Determinism: the walk order, the rank (a pure function of the state) and the tie-breaks are all fixed.
- The evaluator only ever sees end-of-turn states or cut states, never a state paused mid-pick. The static rank only ever sees resolved exits.
- With a generous budget the search is exact.

What it approximates:
- For a large pick, only pick_keep+1 of its outcomes get searched, so the result is a lower bound on the true value of the pick. The real error is the chance that the true best outcome is not in the static top k.
- Outcomes past pick_states are never seen at all. For any-number picks these are the largest subsets, which are rarely best.

Where it can fail:
1. The heuristic pools hand, draw and discard into one per-turn output and does not see this turn's plan. For Purity it will tend to rank "exhaust Defend or Strike" over "exhaust Bash", whatever is left to play this turn. If the best line is "exhaust a card I can't afford this turn", it may be cut. Mitigation: pick_keep is a knob, and the "take nothing" outcome is always there.
2. When an exit leaves a chance node pending (Gambler's Brew draws), estimate is called on the pending state. That works only because the heuristic pools the piles; the draw itself is not ranked.
3. Two different pick start states can, rarely, reach the same internal state. The memo then reuses the subtree pruned by the first plan. That is still a valid sub-choice (a lower bound) and deterministic, but not the second plan's own top k.
4. Exact picks with huge n (no Done) still have their walk capped by pick_states. Past that cap, their deepest completions are missing, and if none are found the pick falls back to exact expansion. To keep this safe, the walk stops but still reports the exits it found. If it found none, no plan is pushed.

**Cost estimate.** Measured hand (Purity+ in a 10-card hand against Jaw Worm, 617 distinct pick starts):

- Tree nodes inside the picks: at most (6+1) paths with up to 5 steps each, sharing prefixes, so about 10-20 per start, or about 6k-12k.
- Pick exits: at most 7 per start, so at most about 4.3k. Many merge, for example "exhaust nothing" from every start already exists in the tree.
- Continuations after the exits: about 600 starts times 7 subtrees, each the size of a no-pick search from that point. 407 of the starts are at 0 energy, where a continuation is only a few nodes (Anger or EndTurn); the 168 starts at 3 or 2 energy carry most of the cost.
- Total: base 14,623 plus about 15k-35k, so about 30k-50k nodes, against 300,645 uncapped. That should fit under the 50,000 cap with few or no cuts. End-of-turn states should come to about 3k-6k, against 34,867.

Off-tree work, which is CPU time but not nodes:
- The walk visits at most 617 times 638 states. Most starts are at 1 or 0 energy with 4-7 cards left, so about 16-128 subsets each; I expect 50k-150k apply_action clones.
- Static rank calls (heuristic::estimate, which has a cache) happen once per exit, about 30k-100k.
- Together that is about the cost of a 100k-node tree build without the memo churn. It is the weak spot: if a profile shows the walk dominating, lower pick_states or add a memo of walks keyed by the start state.

These numbers are my estimates from the measured counts, not measurements.

**Engine changes.** All changes are in engine/src/search.rs, size M (about 120-180 lines):

1. SearchConfig: add pick_exact: u8 (12), pick_keep: u8 (6, 0 = off) and pick_states: u32 (4096). Add them to Default and to the Python binding where SearchConfig is built (py/).
2. A new fn pick_exits(s, cap) -> Vec<(CombatState, Vec<Action>)>: the breadth-first walk with a local Vec plus Index.
3. A new struct Plan { states: Vec<CombatState>, index: Index }, and a plan stack Vec<Plan> in Tree.
4. A new fn Tree::plan_pick(s) -> Option<Plan>. It ranks exits with crate::heuristic::estimate, which needs to become pub(crate) if it is not already.
5. Tree::expand:
   - at a pick start that is not in the top plan, push the plan and pop it on return;
   - in the Decision branch, while a plan is active, filter children through plan membership before calling self.child;
   - keep the cap exemption for picks.
6. SearchResult: add pick_pruned: usize (exits dropped) next to cuts.

No changes are needed in state.rs or heuristic.rs, apart from making estimate visible to search.rs if needed.

**Measurement.** 1. Identity check, done first. On the existing search suite and series without large picks, results must be byte-identical with the feature on and off: same action, options, nodes, leaves, cuts and line. This holds because a pick with 12 or fewer exits skips planning. A cargo test should also assert that pick_keep = 255 with pick_states = u32::MAX gives the same root values as pick_keep = 0 on the Purity+ hand, uncapped. That is the "exact with a generous budget" check.

2. Cost probe on the measured hand, run the same way as the kb measurement purity-search-cost. For pick_keep in {off, 2, 4, 6, 12, 32}, report:
- nodes, uncapped and at 50k;
- distinct end-of-turn states;
- cuts and pick_pruned;
- walk states and wall time.
Targets at pick_keep = 6: at most 50k nodes, zero cuts at the 50k cap, and wall time at most that of today's 50k-capped search.

3. Correctness of the budget. Against the exact uncapped search (300,645 nodes) as ground truth, for each pick_keep, report:
- whether the root action and the full principal line are the same;
- the root value gap (exact minus budgeted, which is always 0 or more);
- at which rank in the static order the true best Purity outcome sits.
Run this over a small set of states with Purity, and with a Gambler's Brew stand-in deck, at 3, 2, 1 and 0 energy. The rank distribution shows how much of the remaining error comes from the static heuristic.

4. Play quality. Run a paired sweep through the job queue (pinned) on decks containing Purity or other any-number picks: today's 50k-capped search against pick_keep = 6 at 50k. Compare win rate and HP lost per fight on the same seeds, plus the decision time per turn. The budgeted version should be at least as good, because it now reaches end-of-turn states the cap used to cut (957 cut states today), while spending fewer nodes.

5. Determinism. Run the probe twice and check that the outputs are identical.

## Pick beam with a learned pick prior (stop-now evaluator lookahead as the fallback and as the teacher)

Search keeps its current exact enumeration for small picks and changes how it handles large ones. In Tree::expand, before building a Decision node at a pick state (s.pick().is_some()), count how many distinct outcomes the pick can end in. For an order-free pick that is the number of sub-multisets of the source pile of size <= left (size == left when exact). For an ordered pick (HandToTop, DiscardToTop) it is the number of sequences. If that count is at most pick_full_limit T (default 32), expand exactly as today. That covers every exact-1 pick (Headbutt, Warcry, Armaments, True Grit+, Offered), so their results do not change.

Above T, the pick state becomes one Decision node whose children are whole-pick completions found by a beam over the engine's own Choose and Done steps. The beam starts at the pick state with width B (default 4). At each step it ranks every legal Choose(c), plus Done when the pick is not exact, by a prior logit. It applies the actions with apply_action, so the engine stays the one source of truth. It keeps the top B partial picks by summed log-softmax, and merges partial picks that reach equal states. That uses the existing afterstate equality, so order-free picks collapse their orders for free, and ordered picks stay distinct because their states differ. Every partial pick also emits its Done-completion as a child, so stopping early, including the empty set, is always among the children. A beam entry that leaves the pick (left reaches 0, or the source runs out) is a completion too. The completions are what the card produces once the pick is over (the next decision or chance), so they go through self.expand like any other state. The evaluator never scores a half-resolved card. Each child is recorded with the Action of its first step, and duplicate completions merge as they do today. The root is unaffected: search() still loops over every legal action at the root. When the agent stands at a pick, its first step is therefore exact, and the beam applies only to the rest of the pick and to picks deeper in the turn.

The prior comes from one of two sources behind one new Evaluator method: fn pick_logits(&mut self, s: &CombatState, acts: &[Action]) -> Option<Vec<f32>>, which returns None by default.
(1) A learned policy head, AlphaZero-style. It is added to the effects-mode value net and shares its trunk. For each candidate card, the logit is an MLP over [that card's entity embedding (built from its effect rows), the pooled state embedding, the pick-kind one-hot and pick_left]. Done gets a logit from the pooled embedding. That costs one forward pass per beam state, and the logits are cached by state hash in the tree. Because cards enter only through their effect rows, an unseen pack card gets a sensible logit from what it does, not from its id.
(2) When the method returns None (heuristic evaluator, ids net, or a net without the head), the fallback is stop-now lookahead. The logit of Choose(c) is the evaluator's value of the completion after Choose(c) then Done, and Done's logit is the value of stopping now. Both are whole-card states, so they are legal to score. This needs no training and is sound for any pack card. It costs about B x left x candidates evaluations per large pick.

Training for (1): the fallback and an uncapped exhaustive search act as teachers. Generate pick states from self-play over pack decks that include any-number and large pick cards, using finetune.py's mutated-content fights for variety. At each pick-step state, run the full search uncapped offline; it is about 300k nodes for the worst case, which is cheap offline. Take its backed-up Q for each child Choose(c) and for Done, and train with cross-entropy against softmax(Q / tau). This is AlphaZero's visit-distribution target with exact Q in place of visits. The loss is added to the value loss on pick rows only. Hold out whole pick cards (for example, train on Purity, Burning Pact and Gambler's Brew, test on Calculated Gamble and Headbutt-like cards) to check generalization.

**Exactness.** What stays exact: every pick with at most T distinct outcomes (all exact-1 picks and small hands) is expanded exactly as now, so existing tests and results are unchanged. Every first step at a root pick is searched in full. Each kept child is a real engine afterstate, scored only after the card resolves, with order-free merging by afterstate equality. Finished combats still score exactly. The output is deterministic: Rust f32 inference on a fixed machine, ties broken by legal_actions order, and the logit cache is keyed by state.

What becomes approximate: for picks over T, only about B x (left+1) completions out of the full set (for example 8 to 25 of 638 sub-multisets) are searched, so the chosen subset can be worse than the exhaustive best. The prior can also misrank cards whose value depends on later plays in the turn. Stop-now lookahead is myopic: exhausting Strike looks bad on its own even when keeping Clash playable is the point. The learned head trained on full-search Q is what fixes that.

Failure cases:
(a) Strongly interacting subsets, where two cards are only good together and each scores badly alone. A beam with B >= 2 and Done-completions at every prefix softens this but does not guarantee it.
(b) A pick kind with no training data. The pick-kind one-hot is all zero, so the head falls back to the card embedding alone. Mitigation: return None for kinds not marked as trained, which switches to the lookahead fallback.
(c) Exact large picks (exhaust exactly 3 of 10) have no stop-now state. The fallback completes the pick greedily in card-id order just to score it, which is weaker. These picks are rare.
(d) A Purity whose real value comes in a later turn (deck thinning). The value net judges that through the afterstate's piles, and only as well as the net itself can.

The search still finds the best line among the lines it keeps. What gets dropped is a set of whole-pick completions the prior ranks low. The node cap is never spent on half-resolved cards.

**Cost estimate.** This is an estimate on the measured hand, not a measurement. The baseline with a no-pick card in Purity's place is 14,623 nodes. Purity's 617 pick starts currently enumerate up to 638 sub-multisets each, plus one node per distinct partial pick. That is most of the 286k extra nodes, and it leads to 34,867 distinct end-of-turn states.

With T=32 and B=4: at 3 energy, the 5 starts each see a 9-card hand, giving roughly 4 x 6 ≈ 20 completions each. At 0 energy, the 407 starts have small hands, many of them with 32 or fewer sub-multisets, so those stay exact. That case is cheap anyway, because at 0 energy the only follow-up is EndTurn. At 1 to 2 energy, the 205 starts give about 15 to 20 completions each. Intermediate Choose nodes are no longer created as nodes; only the completions and their continuations are.

Expected total: about 14.6k (base) + about 617 decision nodes + about 617 x 15 ≈ 9k completions. The continuations after a mid-turn Purity are smaller sub-turns, and many merge in the memo, adding perhaps 10 to 20k more. That is roughly 30k to 45k nodes uncapped, under the 50,000 cap, so 0 cuts, against 300,645 today. End-of-turn states drop from 34,867 to an estimated 5k to 10k.

Prior cost: the learned head needs about 617 x B x left ≈ 12k small forward passes, comparable to today's leaf batch. Stop-now lookahead needs about 10x that in evaluations. That is fine with the heuristic, but with the value net it is about 2 to 4x the current leaf cost. So the head is the target, and lookahead is the bootstrap.

**Engine changes.** engine/src/search.rs (M): new SearchConfig fields pick_full_limit (32) and pick_beam (4), both serialized wherever SearchConfig is mirrored to Python. Tree gets a pick_outcome_count(s) helper (a multiset-subset count, or a sequence count for ordered kinds) and a pick_beam(s, turns, ord) branch in expand. That branch builds the Decision node from completions and adds a logit cache (FxHashMap from state hash to Vec<f32>). Evaluator gets a pick_logits default method that returns None, and search.rs carries the stop-now fallback. engine/src/state.rs (S): a public PickKind::ordered() and a read-only pick_source accessor (or a pick_candidates(&self) -> Vec<(CardId,u8)>); no rule changes. py/src/net.rs (M): load an optional policy-head state dict and implement pick_logits, mapping each Choose(c) to its hand or pile entity row. py/src/features.rs (S): expose the candidate-to-entity index for the pick's source pile. Python stsnet and train (M): the policy head, plus a cross-entropy loss on pick rows only. New dataset script (M): enumerate pick-step states from self-play with mutated content, run uncapped full search on each, and store Q per action. That output goes in datasets/ and can be regenerated, with a clean step that deletes the dataset directory. Tests (S): the T gate leaves every existing search test unchanged; determinism over two runs; a Purity probe test asserting a node count under 50k and that a beam completion includes Done-at-start.

**Measurement.** Probe, as a debug test, deleted after, as in the 2026-11-13 run: the same Purity+ 10-card hand against Jaw Worm with the default SearchConfig. Report nodes uncapped, cuts at 50k, distinct end-of-turn states, and wall time for three settings: full (pick_full_limit = infinity), the beam with stop-now lookahead, and the beam with the learned head. Pass: under 50k nodes and 0 cuts, and the root value within 0.01 of the full search's value, with the same root action or an equal-value one.

Recall probe over a set of large-pick situations (Purity, Burning Pact, Gambler's Brew, Calculated-Gamble-like cards, ordered top picks), at least 200 states sampled from self-play: how often the exhaustive search's best completion is among the beam's kept completions, and the mean value regret (full root value minus beam root value). Report this separately for held-out pick cards the head never trained on; that number is the generalization test. Target: regret under 0.01 on the score scale, and recall at least 90% for the learned head versus the lookahead fallback.

Play quality: a paired gauntlet on pack decks containing these cards, same seeds, beam versus today's capped search. Read win rate and HP lost with confidence intervals. The beam should be no worse and should be faster, because nodes saved on picks go to the rest of the turn under the same cap. Also run a control gauntlet on decks with no large picks, which must be bit-identical because of the T gate.

## Play-last obligation: the search plays a pick card only right before EndTurn or before an action it changes (late-canonical partial-order reduction)

What I read: search.rs Tree::expand memoises on full CombatState for each turns value. legal_actions offers every playable card at every decision, and every distinct candidate at a pick. Purity's sub-multisets are already merged by the memo, so each pick start costs one node per partial multiset. The waste is not at the pick. It is that after each of the 617 play points the rest of the turn is searched again. The line "Purity(X), then Strike, Flex ... EndTurn" reaches the same states as "Strike, Flex ..., then Purity(X), EndTurn", but the first line builds its own chain of in-between nodes.

The rule (from partial-order reduction in model checking): any line u·P(X)·a·w, where action a commutes with P(X), reaches the same afterstates as u·a·P(X)·w. Applying this repeatedly, every line has a canonical form in which P comes immediately before the first action that does not commute with it, or immediately before EndTurn. Moving P later past a chance node only adds information, because P's choice can then depend on the outcome. So every pruned strategy is matched outcome by outcome by an explored one.

Implementation:
(1) Obligation. When the search applies Play(P) for a card whose effects include Effect::Pick (later this can be any action), the child carries a search-only obligation Obl{card: P, hand_before: hand length before P}. It passes through P's pick states and any chance nodes P causes. At the first plain decision state it filters the legal actions to: EndTurn, plus each action a with !commutes_later(state, Obl, a). Taking that next action clears the obligation, or sets a new one if the action is another pick card. Two Purities are dependent on each other, so either order is allowed.
(2) The memo key becomes (CombatState, Option<Obl>), so a state reached with an obligation never reuses a free node and the other way round. The end-of-turn leaf index stays keyed on state alone, so end states still merge by afterstate (owner rule).
(3) Root exemption. A Play(P) taken at the root gets no obligation. That keeps every root option's value exact for solve.rs options and training targets.
(4) commutes_later reads an engine footprint table. Every content element (effect, play condition, trigger hook) gets a read set and a write set over components: HandChoice (a monotone read: picking a subset of the hand), HandExact (a read of the whole hand: Clash's condition, True Grit, Second Wind, Fiend Fire), HandAdd, HandRemoveOther, DrawPile/top order, Discard, Exhaust, Energy (decrements are additive; X-cost is an exact read), CardsPlayed counters, Player/Monster HP, block and powers, plus Everything.
P(X) and a commute when (i) neither reads anything the other writes, except that a's HandAdd against P's HandChoice is allowed in this direction (deferring P only adds candidates), and except additive writes against additive writes; (ii) neither removes or adds a card the other needs (a's own removal from hand is excluded, since X never contains a played card); (iii) no hand overflow: hand_before - 1 + hand_adds(a) <= HAND_LIMIT. The footprints of hooks P triggers come from the state's current powers and relics (on-card-played, on-exhaust: Feel No Pain, Dark Embrace, Dead Branch, Letter Opener, Velvet Choker and so on). Any element without an entry counts as Everything, which makes it dependent and keeps search sound.
In the measured hand: Strike, Defend, Bash, Anger, Cleave, Twin Strike and Flex commute with Purity. Pommel Strike's draw commutes too (it is a HandAdd against HandChoice, and 10 - 1 + 1 <= 10). Only Clash, whose condition reads HandExact, may follow Purity directly. Purity is still played at all 617 points, but after each resolved pick only EndTurn or Clash is searched, not the rest of the turn.

**Exactness.** What stays exact: the value of every node without an obligation, which includes the root and every root option (thanks to the root exemption). The proof is by induction on how far P sits from its canonical position. Each step swaps one commuting pair, and the footprint rules guarantee the two orders give identical CombatStates (same exhaust and discard multisets, same counters). Moving P past a chance node is covered outcome by outcome. The set of distinct end-of-turn leaf states is identical to the unreduced search, and the evaluator still only sees card-boundary states. Results are deterministic: the filter is a pure function of (state, Obl), and actions keep legal_actions order.

What changes: values of nodes that carry an obligation inside the tree. They are lower bounds and only feed max nodes that also see the equivalent line. At the root the best value is unchanged, but where the old argmax was "Purity now, then play on", the reduced tree now gives that value to playing the other card first. With the root exemption the root Play(P) option keeps its exact value, so the chosen action does not change.

Not removed: (a) pick enumeration at all 617 play points, because "Purity then EndTurn" is a real distinct end state at each of them. The 34,867 distinct end states are inherent to afterstate equality. (b) After a dependent action (Purity then Clash), the rest of the turn is unrestricted, so u·P·Clash·Strike and u·Strike·P·Clash both get explored. That leftover redundancy would need sleep sets, which the plan leaves out.

Failure cases, all sound, just weaker: a counter reader in play (Velvet Choker, Letter Opener, Ink Bottle, Normality) or an unclassified element makes everything dependent, and the reduction turns itself off. An exact-hand reader in the hand (Second Wind, True Grit, Fiend Fire) brings back the full subtree after P. Risk: a footprint entry that is wrong makes search unsound. That is why the leaf-set equality probe below is required in the test suite, not optional.

**Cost estimate.** Measured hand, uncapped: about 90k-130k nodes against 300,645 (roughly 2.5-3x fewer). The reasoning:
- Lines where Purity is never played cost about the same as the no-pick baseline, about 15k nodes.
- Each resolved Purity subset costs about 3 nodes: the partial-pick node, the resolved decision node that holds the obligation, and the EndTurn leaf node. Over the roughly 35k distinct resolved subsets (the end states are inherent) that is about 100k. From the play-point counts: 407x~64 + 163x~120 + 42x~220 + 5x~380 is about 57k partial multisets as an upper bound, and merging lowers it.
- Purity followed by Clash adds a branch only where X takes out every remaining non-attack (Defend, Flex): roughly a few thousand to 15k nodes.
- The continuations that used to follow each Purity play point disappear. In the 300k they made up the bulk: about 8.6 nodes per end state, down to about 3.
At the 50,000 cap, cuts fall from 957 to some hundreds. They do not reach zero, because the end-state count alone is near the cap. Overhead: one footprint check per (decision under obligation, action), on bitsets, which is negligible. The memo key grows by about 2 bytes.

*Note 2026-11-14: this estimate is wrong. The memo already merges the reordered continuations, so they were never separate nodes and the reduction can only skip edges. The probe `engine/tests/play_last_probe.rs` confirmed it: with the engine-checked rule the walk reaches the same 74,092 states (0 missing), its keys rise to 102,704 and its applies to 562,820 against 249,179. The judges' "about 100k" repeats the error. See `docs/research/build-plans-2026-11-14/purity-play-last.md` (Step 0 result).*

**Engine changes.** - New engine/src/footprint.rs (M): a Footprint bitset with read, write and additive-write masks; a per-element table next to registry::element_names(); card_footprint(state, card) and potion_footprint, which include the trigger hooks of the state's current powers and relics.
- engine/src/state.rs (S): pub fn commutes_later(&self, p: CardId, hand_before: u8, a: Action) -> bool, holding rules (i)-(iii) and hand_adds(a).
- engine/src/search.rs (S-M): an Obl type; Memo keyed on (CombatState, Option<Obl>) (store the pair, hash both); expand and child gain an obl parameter, carried through pick and chance nodes and set on Play of a pick card, except at the root; the action loop in expand filters by obligation at a plain decision state. The cap logic is unchanged: a pick state stays exempt.
- engine/src/solve.rs (S): root options pass obl = None (the root exemption), plus a SearchConfig flag por: bool (default on after the probe passes) so the A/B probe can turn it off.
- New engine/tests/footprint.rs (S): every element in element_names() has a footprint entry, failing like wording.rs does.
- New engine/tests/por_exact.rs (S): the probe below.
Read only: no repo files were edited for this design.

**Measurement.** 1) Exactness probe, run as a cargo test and as a script over a battery of states. The battery: the measured Purity+ hand against Jaw Worm; variants adding Second Wind, True Grit, Pommel Strike at a full 10-card hand, and Feel No Pain or Dark Embrace in play; plus Gambler's Brew, Warcry (HandToTop, ordered), Armaments, Headbutt, Exhume and Burning Pact states taken from the sweep and db logs. Run each search uncapped with por off and on. Required: bit-identical root value and per-root-option values; the end-of-turn leaf state sets equal as sets; two runs with por on give identical trees (determinism).
2) Cost probe, re-measuring kb measurement/purity-search-cost: nodes uncapped (target at most about 130k, against 300,645), distinct end states (must stay 34,867), and cuts at max_nodes=50,000 (against 957). Repeat with the no-pick baseline hand to confirm no regression (expect about 14.6k).
3) Play-quality read, from a pinned job pair: paired fights at the default 50k cap with decks containing Purity, Gambler's Brew, True Grit and Warcry, por on against off. Read win rate and HP lost per fight, with paired differences and a CI; expect equal or better, since fewer cuts mean fewer heuristic leaves. Also compare wall time per search.
4) Kill switch: if probe 1 ever disagrees, the wrong footprint shows up in the first differing leaf. Fix that entry rather than tuning around it.

## Judge 1

| Design | Soundness | Generality | Savings | Cost |
|---|---|---|---|---|
| Play-last obligation (late-canonical partial-order reduction) | 4 | 3 | 3 | 2 |
| Pick ration (off-tree exit walk, static top-k) | 3 | 3 | 4 | 4 |
| Canonical-order pick walk + resolved-outcome beam | 3 | 3 | 4 | 1 |
| Pick beam with learned pick prior (stop-now lookahead fallback) | 3 | 3 | 4 | 1 |

- **Play-last obligation (late-canonical partial-order reduction):** This is the only design that stays exact, and it goes after the real waste. The code confirms the diagnosis. expand (search.rs:314-365) memoises on the full state, so pick sub-multisets already merge. The cost comes from re-searching the rest of the turn after each of the 617 play points. The weak part is the hand-written footprint table. A presence test (footprint.rs) can check that every element has an entry, but not that the entry is right, and two gaps show up in plain content. (1) Energy is treated as additive-vs-additive, but playability reads energy. Exhausting Sentinel with Purity at 0 energy makes Strike playable only after Purity, so the line Purity(X), Strike has no reordered twin. The rule must treat a legality check as an exact read. (2) Cards in hand with on-play hooks are left out. Pain triggers when another card is played, so exhausting Pain changes whether Strike costs HP; only the hooks of powers and relics are listed. Dark Embrace and Feel No Pain draws are covered by rule (ii) and the chance-node argument. The savings are real but partial, about 100k nodes against 300k. The 34,867 end states are inherent, so the 50k cap still cuts. Better variant: drop the table and test commutation with the engine itself. At a resolved state under an obligation, apply a then P(X) from the state saved before P, and compare with the state after P(X) then a. Prune a only when they are equal (and the chance lists are equal when a draws). That keeps one engine source of truth, is sound for any pack content, and costs a few applies per pruned edge.
- **Pick ration (off-tree exit walk, static top-k):** Cheap: the change stays inside search.rs, and it is exact for picks with 12 or fewer outcomes and under a generous budget. Keeping 'take nothing' is a good floor. It fits under the cap only because it throws away most outcomes, using heuristic::estimate as the ranking. That ranking is myopic: it pools the piles and ignores what is left to play this turn, which is exactly the Purity decision. The plan stack interacts with the memo, which is keyed on state only. A pick-internal state memoised under one plan is reused, already pruned, by another plan (the design admits this; it stays deterministic but is not that plan's own top k). Two cases are left unspecified. When an exhaust trigger leaves a draw pending mid-pick (Dark Embrace), the state has both pending and pick() set, and the walk's 'only pick states' rule does not say how to handle it. An exact large pick can also hit pick_states and keep only its shallow exits. The off-tree walk (up to about 617 x 638 applies) is fine as CPU work. A useful second stage on top of an exact reduction, but on its own it trades the 957 cuts for silent pruning by a weak ranking.
- **Canonical-order pick walk + resolved-outcome beam:** Layer 1 (walking over counts in canonical order) is exact, but it saves far less than claimed. The memo already merges orderings, so partial-pick nodes number at most about 57k, not '150k, half the 300k'. Layer 1 also does nothing about the continuations, which are the bulk. The real savings come from the layer-2 beam. That beam is greedy over levels in card-id order and scores each completion with the evaluator on mid-turn states (the same quality caveat as today's cap cuts). It has the same myopia failure as design 2, plus failure (b), cards that only pay off when exhausted together. Its generality rests on an order_free() tag per pick kind with a test that compares reversed order. It falls back on a chance guard, but deterministic order-dependent triggers on exhaust (Pain-like hand hooks, counters) need the test to catch them. Cost is the highest of the engine-only designs: a new Node kind, a side table for replaying lines, a phased round loop with evaluator batching, and changes to backup and tie keys. Too much machinery for an approximate result.
- **Pick beam with learned pick prior (stop-now lookahead fallback):** The T gate keeps small picks identical, and the first step of a root pick stays exact. Completions are whole-card states, so nothing half-resolved is ever scored. The node savings are similar to designs 2 and 3. Generality is the selling point (an effect-row embedding gives unseen cards a logit), but nothing here shows it works yet, and the hold-out test decides it. Cost is by far the highest. It needs a policy head in net.rs, features, training, and a dataset built from uncapped 300k-node searches on many pick states, all for one card family. Without the head, the stop-now fallback is the same myopic screen as design 3, costing about 10x the evaluations, and 2 to 4x the leaf cost with the net. Worth considering only once a policy head is wanted for other reasons.

**Recommendation.** Build design 1 first, the play-last obligation (exact partial-order reduction), but in the variant that checks commutation with the engine instead of the footprint table. At a decision state that carries an obligation, keep the state from just before P and the resolved pick. For each candidate action a, apply a and then replay P with the same picks from the saved state, and compare with applying a to the current state. If both states are equal (and their chance-outcome lists are equal when a draws), and a was legal before P, the reordered line is already in the tree, so prune a. Otherwise keep it. Keep the root exemption, so every root option's value stays exact, and key the memo on the state plus the obligation. This needs no per-element table, so it stays sound for Sentinel energy, Pain in hand, Dark Embrace and Feel No Pain draws, counters (Velvet Choker, Ink Bottle) and ordered top picks, and the engine stays the one source of truth. It is a small to medium change in search.rs only. Measure in this order. (1) Exactness probe with the reduction off and on, uncapped, over the Purity+ hand plus variants with Sentinel, Pain, Dark Embrace, Feel No Pain, True Grit, Second Wind, Gambler's Brew and Warcry. Required: identical root and per-option values, identical sets of end-of-turn states, and identical results from two runs. (2) Cost on the measured hand: nodes uncapped (expect about 90k-130k against 300,645), distinct end states (must stay 34,867), cuts at 50k (against 957) and wall time; plus the no-pick hand, which should stay about 14.6k. Because the end-state count alone is near the cap, the reduction will not get rid of cuts at 50k. If cuts still matter, add design 2's ration as a second, approximate stage, but only after a pinned paired sweep (win rate and HP lost, decks with Purity, Gambler's Brew, True Grit and Warcry) shows that the remaining cuts hurt play. Rank its outcomes by short search value, not by heuristic::estimate alone. Leave designs 3 and 4 for now: one is too much machinery for an approximate result, the other is unproven and needs a training pipeline.

## Judge 2

| Design | Soundness | Generality | Savings | Cost |
|---|---|---|---|---|
| Play-last obligation (late-canonical partial-order reduction) | 4 | 3 | 3 | 2 |
| Pick ration (off-tree exit walk, static top-k, one path per kept exit) | 3 | 4 | 5 | 4 |
| Canonical-order walk with resolved-outcome beam screening (PickSet macro node) | 3 | 3 | 4 | 1 |
| Pick beam with learned pick prior (stop-now lookahead fallback) | 3 | 4 | 4 | 1 |

- **Play-last obligation (late-canonical partial-order reduction):** This is the only design that stays exact, and the argument holds up against the code. The memo in Tree::expand (search.rs:314-365) is keyed per turns-left on full state equality. Adding the obligation to that key keeps nodes with and without an obligation apart, the root exemption keeps every root OptionScore exact, and the leaf index stays keyed on state alone. Its engineering weak point is commutes_later. It needs a footprint table, with a read set and a write set, for every effect, condition, power and relic hook. That table is a second, hand-kept description of what each element does, which goes against the owner's 'one engine source of truth' rule, and every future pack card has to add an entry. A wrong entry makes search silently unsound wherever the probe battery doesn't reach. The fallback of treating an unknown element as 'Everything' is safe but turns the reduction off. The payoff is limited too. The design itself admits the 34,867 distinct end states are inherent, so at the 50k cap it still cuts hundreds of states, about 2.5-3x fewer nodes, not a fix. Counter readers (Velvet Choker, Ink Bottle, Letter Opener) and exact-hand readers turn it off in exactly the decks where it matters. Worth having later as an exact layer, but a large maintenance cost for a partial gain.
- **Pick ration (off-tree exit walk, static top-k, one path per kept exit):** This is the best engineering trade. All of it sits in search.rs (about 150 lines), and it only calls the engine's own apply_action and legal_actions, so state.rs stays the single source of truth. The pick_exact gate (12 or fewer exits) leaves single-card picks and small hands byte-identical, so golden runs and determinism are protected by construction. heuristic::estimate is already public (heuristic.rs:244). Calling it directly to rank resolved exits keeps the Evaluator contract of one batch per search (search.rs:20-23, 395) intact, and nothing half-resolved is ever scored. Exits are deduplicated by afterstate, so order-free and ordered picks (Purity, Gambler's Brew, Warcry-like top picks) go through one code path. Always keeping the take-nothing exit gives a floor, and a generous budget gives an exact result that a test can check. Risks: (a) the heuristic ranks exits from one start against each other (same energy, same turn), but it doesn't see this turn's remaining plays, so 'exhaust what I can't afford anyway' versus 'keep Clash playable' can be misranked; (b) the memo can reuse a subtree pruned under another start's plan (lower bound, deterministic, rare); (c) the off-tree walk repeats work across the 617 starts, so wall time can be close to today's even when the node count isn't. Measure that. The estimate of about 30-50k nodes with 0 cuts is plausible.
- **Canonical-order walk with resolved-outcome beam screening (PickSet macro node):** Its exact layer 1 is weaker than it claims. The memo already merges orderings (search.rs:317), so the canonical walk mostly stops intermediate pick states from counting as nodes. The states are still built, so the cap gets relief but wall time barely moves. The real savings come from the layer 2 beam, which is an approximation like design 2, but at much higher cost. It adds a new Node::PickSet with a side table of action sequences that every line-extraction or principal-line path has to replay. Its phased rounds call the evaluator during the build. That breaks the Evaluator's one-batch-per-search contract (search.rs:20-23, 395) and the 'children pushed before parents, one pass' ordering the backup relies on (search.rs:397), because placeholders get filled in later. Generality depends on a hand-kept order_free whitelist, plus a guard that falls back to exact expansion whenever a pick draws mid-pick (Dark Embrace). The beam is greedy level by level in card-id order, so it can miss pairs of cards that are only good together. It scores completions that still have energy left, so it has the same myopia as design 2, with more machinery. Highest risk to golden runs and determinism, at about design 2's payoff.
- **Pick beam with learned pick prior (stop-now lookahead fallback):** In the long run this fits the generalization goal best: a policy head over effect-row card embeddings can rank picks for cards it hasn't seen. As a first step it costs the most. It needs a net head in py/src/net.rs and features.rs, Python training, a dataset generator that runs uncapped 300k-node searches per pick-step state, and held-out validation. The untrained fallback (stop-now lookahead) calls the evaluator during expansion. That breaks the one-batch Evaluator contract (search.rs:20-23) and, by the design's own estimate, costs 2-4x the leaf cost with the net. Exact large picks fall back to greedy card-id completion. The T=32 outcome-count gate is a clean way to keep small picks unchanged. The beam and plug-in prior are design 2's structure with a different ranker. So the cheap order is to build design 2 first and later give it a pick_logits hook. Also, without the head the ranking is no better than design 2's heuristic rank, and it costs more evaluator calls.

**Recommendation.** Build design 2 (pick ration) first. It is the only one that is cheap (search.rs only), leaves golden runs untouched (picks with 12 or fewer exits take today's code path), keeps the evaluator's one-batch-per-search contract, and is likely to bring the Purity+ turn under the 50k cap with 0 cuts. Keep the ranking behind one small function (rank_exits(state, exits) -> order) so that design 4's learned pick prior can replace heuristic::estimate later without restructuring anything. Don't build design 3. Its exact layer mostly relabels states the memo already merges, and its beam needs a new node kind plus mid-build evaluator calls. Hold design 1 (POR) as a later exact layer only if the regret numbers show that approximation hurts play. Its per-element footprint table is a second, hand-kept description of effects, which goes against the one-source-of-truth rule, and it still leaves about 35k inherent end states. Measure in this order. (1) Identity: the existing search tests and series are byte-identical with the feature on and off. On the Purity+ hand uncapped, pick_keep=255 with pick_states=u32::MAX equals today's root value and per-option values. Two runs give identical results. (2) Cost: re-run kb measurement/purity-search-cost for pick_keep in {2,4,6,12,32}. Report nodes uncapped and at 50k (target 50k or fewer, 0 cuts against 957), distinct end states, pick_pruned, walk states, and wall time. Wall time decides it, because the off-tree walk repeats work across the 617 starts. Also confirm the no-pick hand stays at 14,623 nodes. (3) Regret: on about 200 sampled turn states with Purity, Gambler's Brew, Burning Pact, True Grit+ and Warcry at 0-3 energy, compute exact uncapped value minus budgeted value, how often the root action matches, and the rank in the static order of the true best exit. If the true best exit is often ranked past k, the heuristic ranker is the weak point, which is the case for adding design 4's prior. (4) Play: a pinned paired sweep on decks with any-number picks, today's 50k-capped search against pick_keep=6. Compare win rate and HP lost (paired differences with a CI) and decision time per turn.

## Judge 3

| Design | Soundness | Generality | Savings | Cost |
|---|---|---|---|---|
| Play-last obligation (late-canonical partial-order reduction) | 4 | 4 | 3 | 2 |
| Pick ration: off-tree enumeration, keep best k by static rank | 3 | 4 | 5 | 4 |
| Canonical-order pick walk with resolved-outcome beam screening | 2 | 3 | 4 | 1 |
| Pick beam with learned pick prior (stop-now lookahead fallback) | 3 | 4 | 4 | 1 |

- **Play-last obligation (late-canonical partial-order reduction):** The only design that stays exact, and the swap argument holds against the code. Tree::expand memoises on the full CombatState, so a line where Purity is played earlier and one where it is played later converge once they reach equal states. Exhaust hooks are batched through unfired_exhausts and fire after the pick ends, so Dark Embrace and Feel No Pain do not cut into the middle of a pick, and the per-swap argument holds. Three ways to break it, all coming from the hand-written footprint table rather than the idea itself. (1) A card's playability compares energy against its cost, which is a threshold read, not an additive write. Example: Purity exhausts a card that gives energy when exhausted (exhaust_card runs the card's own exhausted effects, such as GainEnergy), which makes Bash affordable. If cost counts only as an additive write, the line 'Purity then Bash' is pruned, and 'Bash then Purity' is illegal, so that line is lost. (2) When chance outcomes are sampled (more than cfg.limit, or sample_k > 0), sample_rng includes ord, the count of events so far this turn. Reordering changes ord and so the sampled draws, so 'matched outcome by outcome' holds only for listed outcomes. (3) A wrong or missing footprint entry silently makes search unsound, and there are many elements to keep correct. Fix: drop the table. Decide commutation dynamically with the engine. Apply a to the state before P, replay P's recorded Choose/Done steps, and require equality with applying a after P (and require a to be legal before P). This is afterstate equality (the owner's rule), keeps one source of truth, and removes the footprint risk. When P's resolution spawned chance, carry no obligation (a sound fallback, but no gain for Gambler's Brew). Limits: the 34,867 end states and roughly 57k partial-pick nodes are still there, so it ends near 100k nodes and still cuts at 50k. It cannot fix the cap problem alone. The root exemption is needed and correct.
- **Pick ration: off-tree enumeration, keep best k by static rank:** Sound as a lower bound. Dropped outcomes are removed from the tree, never turned into leaves, so the max never mixes mid-turn evaluator values with backed-up end-of-turn values. The 'take nothing' outcome is always kept. Picks with 12 or fewer outcomes stay byte-identical. The plan filter applies only to Choose and Done, so plain plays in a kept outcome's continuation are not filtered, even though the plan stays on the stack while they are expanded. Weak points. (1) The static rank, heuristic::estimate, pools the piles and cannot see the rest of the turn. Counterexample: exhausting both Defend and Flex is what makes Clash playable, but on its own that outcome ranks low, so the line can be lost. With a pooling heuristic, exhausting anything can look negative: the top k fills with small subsets and Purity degrades toward a no-op. That is a quality failure, not an unsoundness. (2) The off-tree walk still visits every partial multiset (about 57k applies plus about 35k estimate calls), so CPU saving comes only from continuations. Nodes go down a lot more than wall time. (3) Two different pick starts sharing an internal state reuse a subtree pruned under another plan. This is rare, because the exhaust pile tells such states apart. Mid-pick chance is not a problem today, because exhaust hooks are batched. Add a guard anyway. Only search.rs changes, size M, and the identity tests are easy. This is the best design for getting under the cap.
- **Canonical-order pick walk with resolved-outcome beam screening:** Layer 1, the canonical walk, is exact, but it saves less than claimed. The memo already merges partial multisets, and the cost is mostly in the continuations, not the partial nodes. So layer 1 alone removes about 57k of the 300k nodes, not about 150k. Layer 2 has a real soundness problem. Screened-out outcomes become evaluator leaves 'with the values they already have'. Those are mid-turn completions, scored before the turn's remaining energy and cards are played, and they compete in a max against fully expanded end-of-turn values. Any evaluator that values unspent hand cards or energy (the pooling heuristic does) will rate a mid-turn completion above its own played-out line. The max then picks a node that was never searched. Counterexample: at 3 energy, the completion 'exhaust nothing' still holds 3 energy and a full hand, so its screened value beats expanded lines that spent the energy. The beam over card-id levels is greedy in an arbitrary order: pairs that only pay off together are dropped at level 1. HandToTop/DiscardToTop need sequences, which blow up beyond the beam. Cost is the highest of the four (L): a new PickSet node, a side table to replay lines, an evaluator inside the build, round-based building. The batched evaluation (layer 3) is a good idea that could be reused elsewhere. Drop layer 2's leaf mixing, or keep only layer 1.
- **Pick beam with learned pick prior (stop-now lookahead fallback):** Structurally sound. Kept completions are real resolved engine states, beam entries merge by afterstate equality, outcomes that are not kept are dropped rather than scored, the Done-completion at every prefix keeps 'stop early' and 'take nothing', and the T gate leaves small picks unchanged. Problems. (1) The stop-now fallback is as short-sighted as designs 2 and 3. Counterexample: exhausting Strike looks bad on its own, even when the point is to clear non-attacks for Clash. The teacher that fixes this needs uncapped 300k-node searches per pick state and a policy head with a dataset pipeline. That is the largest cost and the biggest unproven step. Generalizing to unseen cards through effect rows is plausible but untested. (2) A Decision node that lists completions under their first-step Action breaks the principal line: line extraction moves from a first step straight to a completion and skips the Choose steps in between. Today's agent re-searches at every decision, so play would still work, but solve.rs lines and logs would be wrong. (3) Exact large picks are completed greedily in card-id order to be scored, which is arbitrary. (4) Gating on the count of sub-multisets does not track cost: at 0 energy most starts exceed 32 outcomes yet cost little, so the gate puts the approximation where it saves least. Worth it later, once the pick-state data exists. Too costly to build first.

**Recommendation.** Build two layers, in order. Neither is enough alone, because the 34,867 distinct end-of-turn states are inherent to exact search under afterstate equality, so no exact design gets this turn under 50k nodes.

1. First, design 1 (play-last obligation), with one change: replace its hand-written footprint table with a dynamic commutation check done by the engine. At a decision that carries an obligation, an action a is pruned only when three things hold:
- a is legal in the state before P;
- applying a there, then replaying P's recorded Choose/Done steps, gives exactly the CombatState of applying a after P;
- P's resolution spawned no chance.

This uses only afterstate equality (the owner's rule) and the engine as the single source of truth. It cannot be broken by a wrong table entry, such as cost-as-a-threshold-read or sampled-chance ord drift. It works for any pack card without per-element upkeep. Keep the root exemption and memo key (state, Option<Obl>).

Measure (as a cargo test and a probe script):
- With POR on and off, uncapped, on the Purity+ hand and on variants (Second Wind, True Grit, an energy-on-exhaust card in hand, Feel No Pain, Dark Embrace, Gambler's Brew, Warcry, Headbutt): root value and each root option's value bit-identical, end-of-turn leaf sets equal as sets.
- Two runs with POR on give identical trees.
- Nodes against 300,645 (expect about 100k), cuts at 50k against 957, the no-pick baseline unchanged at 14,623, and the extra apply_action cost of the check in wall time.

2. Then, design 2 (pick ration) as the budgeted layer for the 50k cap. Of the approximate designs it is the only one that never mixes unexpanded mid-turn evaluator values into the max: dropped outcomes are removed, 'take nothing' is always kept, and it changes only search.rs. Test exactness first: pick_keep=255 with an unbounded walk must equal pick_keep=0. Then, against the exact uncapped search (with POR) as ground truth, sweep pick_keep over {2, 4, 6, 12, 32} on about 200 sampled turns from decks with Purity, Gambler's Brew, Burning Pact and Warcry. Read four things:
- the root value regret;
- how often the chosen action matches;
- where the true best outcome sits in the static order (this shows how short-sighted heuristic::estimate is, Clash-style cases included);
- nodes, cuts, and wall time with the walk included.

Then run a pinned paired sweep (same seeds) against today's 50k-capped search. Read win rate and HP lost with confidence intervals.

If the static-rank rows show heavy short-sightedness, design 4's learned pick prior becomes the next step. Its training targets (exact Q per pick step) can come from step 1's cheaper exact search. Skip design 3's leaf-mixing screening. Only its exact canonical walk (layer 1) and its batched evaluation (layer 3) are worth reusing.
