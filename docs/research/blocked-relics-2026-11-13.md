# Blocked Act 1 combat relics: game behaviour and missing engine pieces (2026-11-13)

Research for `docs/specs/blocked-relics.md`. Five readers read each relic's class in the installed
`desktop-1.0.jar` (javap) and the engine code; a skeptic per group re-read the jar and the code and
tried to refute each finding. Each entry gives the reader's finding, then the skeptic's verdict.
Where they differ, the skeptic's correction wins unless the build session's own read of the code shows otherwise.

## Preserved Insect

- **Size:** S
- **Game:** relics.PreservedInsect.atBattleStart (COMMON; MODIFIER_AMT = 0.25f set in <init>): if AbstractDungeon.getCurrRoom().eliteTrigger, for each monster in the room's MonsterGroup: if currentHealth > (int)(maxHealth * (1 - 0.25f)) then currentHealth = (int)(maxHealth * 0.75f) (a direct field write plus healthBarUpdatedEvent; not damage(), so no onBloodied, no wasHPLost, no block). maxHealth is unchanged. Then it queues RelicAboveCreatureAction with addToTop (visual only). It acts in elite rooms only. For integer max HP under 2^24, (int)(m*0.75f) = floor(3m/4).
- **Missing in the engine:** One effect: CapHp { amount: i16, num: i16, den: i16, target: Target }. It sets each target's HP to min(hp, amount + max_hp*num/den) as a direct write: no HP-loss hooks, no bloodied, no death check needed because the result is at least 1. It goes in effects.rs, registry parse, element_names and wording.json. Draft: {"id": "Preserved Insect", "rarity": "common", "fights": ["elite"], "hooks": [{"trigger": "CombatStart", "condition": "Always", "effects": [{"CapHp": {"amount": 0, "num": 3, "den": 4, "target": "AllOpponents"}}]}]}
- **Shares the piece with:** Neow's Lament (same CapHp with amount 1, num 0). Nothing else in Act 1 content sets HP directly.
- **Risk:** Low. No codec change: HP is already encoded, and it is an effect, not a new trigger. The direct write must skip state.rs lost_hp, OwnerBloodied and OwnerLostHp, as the game does: Lagavulin wakes and the slimes split only through damage(). It needs a net effect column (audit #9 names atoms that write no column) or an explicit 'no column' decision. Golden: the elite fights' starting HP changes only when the relic is held.
- **Skeptic:** partly. Jar facts confirmed (relics.PreservedInsect.atBattleStart: eliteTrigger gate, currentHealth > (int)(maxHealth*(1f-0.25f)) then currentHealth = (int)(maxHealth*0.75f) by putfield plus healthBarUpdatedEvent, then addToTop RelicAboveCreatureAction; tier COMMON, id 'PreservedInsect'). Two small corrections. (1) The gate is the room flag eliteTrigger, not the room type: events.exordium.DeadAdventurer (Act 1) and events.city.Colosseum also set eliteTrigger = true, so 'elite rooms only' is slightly narrow. fights:["elite"] is right only if the engine labels the Dead Adventurer fight as elite. (2) 'The result is at least 1' does not hold for amount 0: floor(3m/4) = 0 when m = 1. No real monster has max HP 1, so a debug_assert or a max(1) is enough. The engine claim stands: no existing effect writes HP without hooks. LoseHp goes through lost_hp, which fires OwnerBloodied (state.rs:3944-3966), and element_names has no SetHp-like effect. CapHp is a real missing atom, and size S is right.

## Neow's Lament

- **Size:** S
- **Game:** relics.NeowsLament (SPECIAL, internal id "NeowsBlessing"; <init> sets counter = 3). atBattleStart: if counter > 0, counter -= 1, and if that makes it 0, setCounter(-2) (used up, text and tips swapped). Then flash, and every monster in the room gets currentHealth = 1 as a direct write plus healthBarUpdatedEvent, followed by an addToTop RelicAboveCreatureAction. It acts in every room kind, bosses included. When the counter is <= 0, nothing happens. It only touches monsters present at battle start. Slime Boss at 1 HP dies to any hit, so its split (checked in damage() only while not dying) never happens.
- **Missing in the engine:** The same CapHp effect as Preserved Insect, nothing else. Counter conditions run in list order (Pen Nib relies on this), so order the hooks 1, 2, 3 so that one decrement can't cascade. Draft: {"id": "Neow's Lament", "rarity": "event", "counter": 3, "hooks": [{"trigger": "CombatStart", "condition": {"CounterIs": 1}, "effects": [{"CapHp": {"amount": 1, "num": 0, "den": 1, "target": "AllOpponents"}}, {"SetCounter": -2}]}, {"trigger": "CombatStart", "condition": {"CounterIs": 2}, "effects": [{"CapHp": {"amount": 1, "num": 0, "den": 1, "target": "AllOpponents"}}, {"SetCounter": 1}]}, {"trigger": "CombatStart", "condition": {"CounterIs": 3}, "effects": [{"CapHp": {"amount": 1, "num": 0, "den": 1, "target": "AllOpponents"}}, {"SetCounter": 2}]}]}
- **Shares the piece with:** Preserved Insect (CapHp). Carrying the counter across fights is R2, the run layer. Inside one fight, a caller passes (name, counter).
- **Risk:** Low in combat, but these fights become trivial: they can distort training and evaluation stats if the relic is handed out freely. The run layer must carry the counter (R2); it is out of scope here. The solved DB keys follow the codec's relic section (counter included), so this is fine. The hook order (1, 2, 3) is a trap: written 3, 2, 1, the hooks would cascade to -2 in one pass. Test it.
- **Skeptic:** confirmed. Jar confirmed (relics.NeowsLament: id 'NeowsBlessing', SPECIAL, <init> counter = 3; atBattleStart: if counter > 0 then decrement, and on reaching 0 setCounter(-2); every monster gets currentHealth = 1 with no room check). The engine runs relic hooks in list order and reads CounterIs live for each hook (state.rs run_relic_hooks ~3084 and player_hooks_outside ~2668), so the 1, 2, 3 order is needed and correct. Written 3, 2, 1, the hooks would cascade. Relic counters already load (the 'counter' relic_rule, and Ancient Tea Set uses -2). Size S, with the shared CapHp, is right.

## Paper Phrog

- **Size:** S
- **Game:** relics.PaperFrog has no combat methods (UNCOMMON, Ironclad pool). The rule lives in powers.VulnerablePower.atDamageReceive(float, DamageType): only for DamageType.NORMAL. If the owner is the player and the player has 'Odd Mushroom', the factor is x1.25. Else, if the owner is a monster and the player has 'Paper Frog', it is x1.75. Otherwise x1.5. THORNS and HP_LOSS damage are unaffected. The result is floored once at the end of the damage calculation. 1.75 = 3/2 * 7/6 exactly, and 1.75f, 0.75f and 1.25f are exact in binary, so the game's float chain equals the engine's rational product rounded once.
- **Missing in the engine:** A static condition on a power held by the other creature: StaticCondition::OpponentHolds(Power). It holds when the damage's target (dst) holds the power with stacks > 0; with dst None (shown_damage) it is false. static_holds needs the dst creature passed in (state.rs interpret_attack_damage_to currently calls static_holds(who, cond) only). It follows the helper-power pattern (Strike Dummy, Torii): pack power PaperPhrog {"statics": [{"modifies": "DamageDealt", "stage": "Multiply", "amount": 0, "num": 7, "den": 6, "condition": {"OpponentHolds": "Vulnerable"}}]}, relic {"id": "Paper Phrog", "rarity": "uncommon", "powers": [{"power": "PaperPhrog", "amount": 1}]}. It needs element_names and wording.json entries.
- **Shares the piece with:** Odd Mushroom (the same 'holds a power' static condition, owner side). R15 has only these two in Act 1. The helper pack power pattern is shared with Strike Dummy, Torii, The Boot and Tungsten Rod.
- **Risk:** Exactness: the interpreter multiplies the attacker's 7/6 before the target's 3/2 and rounds once, which matches the game. The fast path in attack_damage_to is skipped once a generated power is held, which is correct but slower. Hand-computed readers miss it: heuristic.rs (around 304/344 hard-codes vuln x1.5) and agent::incoming_damage (audit #5) underestimate the Vulnerable bonus. The helper power takes 1 of the 12 player power slots (POWER_CAP, audit #11) and shows to the net as a pack power. Codec: new static-condition rows for pack powers only; no state field.
- **Skeptic:** confirmed. Jar confirmed: powers.VulnerablePower.atDamageReceive, NORMAL only. It checks the player-owner Odd Mushroom branch (x1.25f) first, then a non-player owner with 'Paper Frog' (x1.75f), else x1.5f. Relic id 'Paper Frog', UNCOMMON. Engine: StaticCondition has only Always, CardInPlayTagged and OwnerHpAtMostHalf (hooks.rs:252). static_holds(owner, c) takes no dst (state.rs:3661). interpret_attack_damage_to multiplies num/den and floors once (state.rs ~3693), so the 7/6 rational composition is exact. The Condition word TargetHas exists, but only for hooks, not for statics, so no existing word covers it. Size S is right.

## Odd Mushroom

- **Size:** S
- **Game:** relics.OddMushroom has no combat methods (SPECIAL, from the event Hypnotizing Colored Mushrooms). In powers.VulnerablePower.atDamageReceive, for NORMAL damage, when the owner is the player and AbstractPlayer.hasRelic("Odd Mushroom"), the factor is x1.25 instead of x1.5. It is checked before the Paper Frog branch, which applies to monsters only, so the two never conflict. The result is floored once at the end. 1.25 = 3/2 * 5/6.
- **Missing in the engine:** StaticCondition::OwnerHolds(Power), the owner-side form of the same new word. It needs no dst, so static_holds(owner, ..) already has what it needs. Helper pack power OddMushroom {"statics": [{"modifies": "DamageTaken", "stage": "Multiply", "amount": 0, "num": 5, "den": 6, "condition": {"OwnerHolds": "Vulnerable"}}]}, relic {"id": "Odd Mushroom", "rarity": "event", "powers": [{"power": "OddMushroom", "amount": 1}]}. Build it as one atom with Paper Phrog: Holds { side: Owner|Opponent, power }.
- **Shares the piece with:** Paper Phrog (R15).
- **Risk:** The same as Paper Phrog. The bigger reader risk is that intents and the agents' incoming damage use the player's Vulnerable. move_attacks goes through attack_damage_to, so it routes correctly to the interpreter. But heuristic.rs vuln_p and agent::incoming_damage hard-code x1.5 and would overestimate incoming damage. A test should pin the interpreter equal to the game for Weak + Vulnerable + Mushroom (e.g. base 9 with Weak: floor(9*0.75*1.25)=8).
- **Skeptic:** confirmed. Jar confirmed (same VulnerablePower.atDamageReceive branch, x1.25f for a player owner; relic SPECIAL, id 'Odd Mushroom'). OwnerHolds needs no dst. move_attacks goes through attack_damage_to, which drops to the interpreter when a generated power is held (state.rs:3588), so intents come out right. Hand copies elsewhere (audit #5) stay a reader risk, as the research says. The example floor(9*0.75*1.25) = 8 checks. Size S, shared with Paper Phrog.

## Hand Drill

- **Size:** M
- **Game:** relics.HandDrill.onBlockBroken(AbstractCreature m) (SHOP) calls flash, then addToBot(RelicAboveCreatureAction(m)), then addToBot(ApplyPowerAction(m, player, new VulnerablePower(m, 2, false), 2)). It is called from core.AbstractCreature.brokeBlock, which iterates the player's relics only when the creature is an AbstractMonster. brokeBlock is called from AbstractCreature.decrementBlock (via AbstractMonster.damage) whenever the damage type is not HP_LOSS, currentBlock > 0 and damage >= currentBlock, an exact break included. So any monster-damaging source counts: attacks, Thorns and other THORNS-type damage such as Combust, the Mercury Hourglass PlainDamage, and potions. Timing: addToBot from inside the DamageAction, so the Vulnerable lands after every action the card already queued (later hits of Twin Strike, Pummel or Sword Boomerang don't get x1.5) and after the card's UseCardAction. ApplyPowerAction with source = player passes through Artifact and fires Champion Belt (Weak 1). It does nothing if the monster is dead by then (the action checks isDeadOrEscaped).
- **Missing in the engine:** (1) A trigger OpponentBlockBroken: the player's hooks (relics, then powers), Target::Opponent = that monster. It fires in the monster-damage path when block > 0 and the non-HP-loss damage is >= block. (2) Deferral: the hook must run after the card resolves, not at once. Add a per-monster side count beside deferred_block (e.g. block_broken[MAX_MONSTERS]: u8), drained in card_resolved, and drained after the monster's move when Thorns breaks a block in the monster turn. That is the audit #29 side-counter pattern. Once the trigger exists, the entry is writable: {"id": "Hand Drill", "rarity": "shop", "hooks": [{"trigger": "OpponentBlockBroken", "condition": "Always", "effects": [{"Apply": {"power": "Vulnerable", "amount": 2, "target": "Opponent"}}]}]}.
- **Shares the piece with:** R40 is alone in Act 1. The deferral shares the after-card machinery with Sharp Hide (Hook::after_card), deferred_block, and Champion Belt's 'lands at once' simplification. All of them are stopgaps for the #29 action queue.
- **Risk:** Timing is the real risk. Applying it immediately would be wrong for multi-hit cards (Twin Strike, Pummel, Sword Boomerang, Whirlwind), which do tell the difference, unlike the Champion Belt case. The new per-monster counter is state the codec must write (only when nonzero, to keep old bytes) and the afterstate key must include it. It should be zero between actions, so it may need no codec at all if it is drained inside the same step: verify. The net needs a trigger column. Hand Drill's Vulnerable must fire OwnerApplied (Champion Belt), which works because it is not an OwnerApplied hook itself. A Vulnerable applied during the monster turn via Thorns decrements at that round's end (source is the player, so justApplied is false), as the engine's ROUND_END_POWERS handling should already do: test it.
- **Skeptic:** partly. Jar facts confirmed: relics.HandDrill.onBlockBroken does addToBot RelicAboveCreatureAction, then addToBot ApplyPowerAction(m, player, Vulnerable 2) (SHOP, id 'HandDrill'). core.AbstractCreature.brokeBlock iterates the player's relics only when this is an AbstractMonster. decrementBlock calls it on non-HP_LOSS damage with block > 0 when damage > block, and also on an exact break (offsets 100 and 121). AbstractMonster.damage calls decrementBlock. One correction to the reasoning: in the game, Twin Strike, Pummel and Whirlwind fix their damage when the card is used (a precomputed DamageInfo or multiDamage), so even an immediate Vulnerable would not change their later hits. Only actions that recompute at hit time tell the difference: AttackDamageRandomEnemyAction (Sword Boomerang) calls calculateCardDamage per hit. The deferral is still required, because the engine's deal() computes each hit at hit time through self.attack (state.rs:3321-3333), so an immediate Vulnerable would wrongly boost every multi-hit card in the engine. The ordering of Artifact consumption against the card's own debuffs (Uppercut) also depends on the deferral. There is no existing block-broken trigger: grep finds nothing, and the trigger list in registry.rs:3088 has none. card_resolved exists (state.rs:2900), and so does the deferred_block side-counter pattern (state.rs:1218, codec.rs:317). Size M is right. The doc mismatch the research flags (Hand Drill cited only on the attack path) is valid.

## Strange Spoon

- **Size:** M
- **Game:** relics.StrangeSpoon has no combat methods (SHOP). The rule lives in actions.utility.UseCardAction. The constructor sets exhaustCard = card.exhaustOnUseOnce || card.exhaust; CorruptionPower.onUseCard also sets it for Skills. In update(): spoonProc = false; if exhaustCard && player.hasRelic("Strange Spoon") && targetCard.type != POWER, then spoonProc = AbstractDungeon.cardRandomRng.randomBoolean() (50%). If !exhaustCard, or spoonProc, the card is not exhausted: the relic flashes and it goes to the discard pile (or the draw pile for rebound/shuffleBackIntoDrawPile). No onExhaust fires: Feel No Pain, Dark Embrace and Charon's Ashes get nothing. It only covers played cards, including Havoc's exhaustOnUseOnce plays. It does not cover exhaust-from-hand (True Grit, Second Wind, Burning Pact, Fiend Fire), Ethereal end-of-turn exhaust, or Power cards.
- **Missing in the engine:** A chance event at the played card's destination. In state.rs finish_card, on the exhaust branch (exhaust || d.exhaust || exhausts_played) for a non-copy, non-Power card while a spoon relic is held: pause with a new ChanceEvent::ExhaustSave (2 outcomes, 1/2 each) before exhaust_card and fire_exhausts. Outcome 0 exhausts; outcome 1 sends the card to discard. The relic needs a property: a new RELIC_KEYS key such as "exhaust_save": true, which audit #31 warns about, or a helper pack power with a replacement on 'played card would exhaust'. Not writable as JSON today: runs_outside_a_card refuses random effects in hooks, and there is no exhaust replacement.
- **Shares the piece with:** Alone in Act 1 (R45). The 'pause at a card's destination' chance pattern sits beside RandomExhaust (True Grit) and TakeTop. Nothing else replaces exhaust in Act 1.
- **Risk:** Search cost: every exhausting play by a Spoon holder becomes a 2-way chance node, with distinct afterstates (pile contents and Feel No Pain block differ). That doubles branching for Corruption/Exhaust decks. Codec: a new pending ChanceEvent tag, plus a stage that can pause in finish_card; finish_card is currently not a pause point, so the stage must remember 'card placed but not yet filed'. Ordering: the roll must come before fire_exhausts/unfired_exhausts so a saved card fires no exhaust hooks. Exclude replay copies (they go to no pile). Rules/golden version bump, and an element_names/wording.json entry.
- **Skeptic:** confirmed. Jar confirmed: actions.utility.UseCardAction.update returns early for POWER cards (offset 198), then spoonProc = cardRandomRng.randomBoolean() only when exhaustCard && hasRelic('Strange Spoon') && type != POWER. On spoonProc, it flashes and takes the rebound / shuffleBackIntoDrawPile / returnToHand / discard path; otherwise moveToExhaustPile, which is where the onExhaust hooks fire. Engine: finish_card(card, copy, exhaust) at state.rs:2610 has exactly the branch order copy, then Power, then exhaust || d.exhaust || exhausts_played (line 2623) as claimed. runs_outside_a_card (registry.rs:2395) refuses random effects in hooks, and no exhaust replacement exists (the replacement_event list has none). So it is blocked as stated, and size M is right. The extra note that the game also honours returnToHand/rebound on a save is already in the research.

### Group notes

All six were checked against the installed desktop-1.0.jar with javap. Paper Phrog, Odd Mushroom and Strange Spoon have no combat methods of their own: their rules sit in powers.VulnerablePower.atDamageReceive and in actions.utility.UseCardAction.update. Hand Drill is called from core.AbstractCreature.brokeBlock, via decrementBlock, for monsters only.

Smallest pieces, in build order:
1. **CapHp effect.** CapHp { amount, num, den, target } is one atom, size S, and unblocks Preserved Insect (0 + 3/4 max, fights: elite) and Neow's Lament (1 + 0). Write Neow's Lament's hooks in the order CounterIs 1, 2, 3 so that one decrement can't cascade within the pass, the same sequential evaluation Pen Nib relies on.
2. **Holds-a-power static condition.** StaticCondition::Holds { side: Owner|Opponent, power } is one atom, size S. Paper Phrog and Odd Mushroom use it through helper pack powers with Multiply 7/6 and 5/6. The Opponent side needs dst passed into static_holds. The rational composition is exact against the game's float math, because 1.75, 1.25 and 0.75 are exact binary floats and the floor happens once. This closes the doc's open check ("whether two static multiplies compose exactly").
3. **Hand Drill**, size M: a new trigger OpponentBlockBroken plus a deferral to after the card resolves. The deferral is needed because multi-hit cards really do tell 'at once' from 'after the card' apart. That is an audit #29 side counter.
4. **Strange Spoon**, size M: a chance pause in finish_card plus a relic property. Its search cost doubles branching on every exhausting play.

Doc mismatch: the Hand Drill row in docs/research/act1-relics-potions.md cites only the attack path (Monster.cpp 433). The jar fires it on any non-HP_LOSS damage that breaks a monster's block, Thorns and THORNS-type damage included.

The scratch folder relics-combat-start was deleted. No repo files were edited.

## Runic Pyramid (R21)

- **Size:** S
- **Game:** RunicPyramid is an empty boss relic with no hooks. The behaviour sits in actions.common.DiscardAtEndOfTurnAction.update. First it moves retain/selfRetain cards to limbo and queues a RestoreRetainedCardsAction. Then, only when !player.hasRelic("Runic Pyramid") && !hasPower("Equilibrium"), it queues one DiscardAction per card left in hand. Either way it then calls triggerOnEndOfPlayerTurn on a shuffled copy of the hand, and AbstractCard.triggerOnEndOfPlayerTurn queues an ExhaustSpecificCardAction when isEthereal. So under the Pyramid every non-retained, non-ethereal card stays in hand. Ethereal cards (Dazed, Ghostly Armor) still exhaust, and a retained ethereal card does not, because it is already in limbo. Turn-end cards such as Burn keep firing every turn because they stay in hand. The next turn's draw of 5 lands on the kept hand. The hand cap of 10 still applies: DrawCardAction stops at a full hand, as the engine's draw does (chance.rs: space = HAND_LIMIT - hand.len()).
- **Missing in the engine:** One rule word plus one branch in state.rs end_turn's hand loop. Suggested shape: a power rule "keeps_hand": true (the power_rule family, with words in content/wording.json and a Rule(KeepsHand) rule row). Relics have no statics, so the relic carries it through a helper pack power, the way Ginger uses GingerWard. The loop becomes: retain -> keep; else ethereal -> exhaust; else owner holds keeps_hand -> keep; else discard. Clearing free_in_hand stays as it is (every mark ends with the turn). Draft: power {"id": "PyramidWard", "keeps_hand": true}; relic {"id": "Runic Pyramid", "rarity": "boss", "powers": [{"power": "PyramidWard", "amount": 1}]}. A relic key "keeps_hand" in RELIC_KEYS would also work, but the net would then need a new relic-row column. The power rule reuses the rule-row path.
- **Shares the piece with:** Equilibrium (Defect, the same check in the same method; out of scope). Retain (the same loop). Well-Laid Plans (Silent, a partial keep through a decision; deferred). It makes Unceasing Top fire less often and keeps Burn and curses in hand across turns.
- **Risk:** No codec change: the rule comes from content, and the hand is already a PileN<HAND_LIMIT>. The net sees a new rule row name, and nets with a saved layout without it read nothing. Search cost goes up: hands stay larger, up to 10 entries, so there are more actions per turn and more distinct states. Turn-start draws into a full hand give 0 cards, which the engine already handles. There is no game check to compare against yet, so a recorded Pyramid fight is needed. It costs a power slot (12-slot cap).
- **Skeptic:** partly. The jar check holds: DiscardAtEndOfTurnAction.update skips the DiscardActions only when !hasRelic("Runic Pyramid") && !hasPower("Equilibrium"), and it still moves retained cards to limbo and calls triggerOnEndOfPlayerTurn (ethereal exhaust). One claim is wrong: 'Burn keeps firing every turn because it stays in hand'. Burn, Regret and Decay act at turn end through triggerOnEndOfTurnForPlayingCard: it sets dontTriggerOnUseCard and adds a CardQueueItem, so the card is auto-played. UseCardAction.update then calls hand.moveToDiscardPile on it (bytecode 464-471). Under the Pyramid these cards go to the discard pile after they fire. They are not kept, and they fire again only after they are redrawn. The engine runs turn_end effects while the cards are in hand and then sorts them in the hand loop, so the proposed branch order needs one more step: retain -> keep; ethereal -> exhaust; the card has a non-empty turn_end (the def's turn_end list) -> discard; keeps_hand -> keep; else discard. The 'keeps Burn and curses in hand' line in shares should also be fixed: only curses without a turn-end play stay (Parasite, Injury, Clumsy and the like; Clumsy is ethereal, so it exhausts). The other engine claims check out: the hand loop is at state.rs 2802-2810, PowerRules and POWER_RULE_KEYS (forbids, sets_cost, exhausts_played) form the rule-row family, GingerWard/Ginger is the helper-power pattern, and RELIC_KEYS has no statics or rule key. Size S stands. The jar also has RetainCardPower (Well-Laid Plans) checking Runic Pyramid; that is Silent and out of scope, as the research says.

## Calipers (R20)

- **Size:** S
- **Game:** Calipers is an empty rare relic. Its constant BLOCK_LOSS = 15 is used only in the description. The behaviour sits in actions.GameActionManager.getNextAction's turn-start block (bytecode 2127-2177). After the start-of-turn relics, cards, powers and orbs are applied, and after the turn counter resets: if !hasPower("Barricade") && !hasPower("Blur"), then without Calipers player.loseBlock() takes all block, and with Calipers player.loseBlock(15) runs. core.AbstractCreature.loseBlock(int,boolean) does currentBlock -= amount and clamps it at 0. So block becomes max(0, block - 15), and Barricade or Blur stop any loss first. This runs before the turn's DrawCardAction is queued. The start-of-turn relic and power effects are queued actions, so they resolve after the loss. That matches the engine, which sets player.block = 0 before pre_draw_hooks (state.rs, Stage::MonsterRolls arm).
- **Missing in the engine:** The same piece as Barricade: a power rule for block lost at the player's turn start. Suggested shape: "block_loss": n, the most block lost (0 means keep all). It is read where state.rs (around line 2526) sets player.block = 0. The fewest lost wins, since Barricade beats Calipers in the game's if-order. Draft once it exists: power {"id": "CalipersWard", "block_loss": 15}; relic {"id": "Calipers", "rarity": "rare", "powers": [{"power": "CalipersWard", "amount": 1}]}.
- **Shares the piece with:** Barricade (C12, the same rule at 0). Blur (Silent, the same check, as a countdown power). Monster-side Barricade (Spheric Guardian, Act 2; the engine resets monster block at state.rs end_turn, about line 2818; I did not check the game's monster side). Body Slam and Entrench gain value. Orichalcum's OwnerBlockIs 0 test at turn end is not affected, because the loss happens at turn start.
- **Risk:** There are two player block-reset sites. One is state.rs at the turn start. The other is search.rs line 302, where cfg.leaf_clear_block zeroes the leaf's block. That one must apply the same rule, or every leaf undervalues kept block. Also check agent and heuristic incoming-damage estimates and the leaf/projection helpers (turn_start_leaf, projected_leaf_with) for any assumption that block is zero at turn start. Nothing changes in the codec. It adds a new rule row (wording plus a net layout name). Kept block grows over many turns, and the engine's player.block is a 16-bit integer; this needs checking but is fine in practice.
- **Skeptic:** confirmed. GameActionManager.getNextAction 2127-2177 matches exactly: hasPower Barricade skips the loss, else hasPower Blur skips it, else without Calipers loseBlock(), with Calipers loseBlock(15) (bipush 15). This runs after applyStartOfTurnRelics/Cards/Powers/Orbs and the turn++, and before the DrawCardAction at 2187. The engine sites are as stated: state.rs:2526 player.block = 0 in the MonsterRolls arm before the pre-draw hooks, and search.rs:301-302 leaf_clear_block. The only string references are GameActionManager, RelicLibrary and Calipers itself, so no other code reads the relic. Size S stands.

## Barricade (C12, Ironclad rare Power)

- **Size:** M
- **Game:** cards.red.Barricade costs 3, or 2 upgraded (upgradeBaseCost(2)). It is a Power aimed at self. use() scans p.powers for "Barricade" and only when the player has none queues ApplyPowerAction(new BarricadePower(p)). powers.BarricadePower has id "Barricade" and amount -1, so it shows no number and has no hooks. That means draw' = d-k with discard D, or d+D-k with discard 0 if k>d. The simple 'old k <= draw.len() < new n' test misses the second fire and, in edge cases, gives the wrong count.

Two fires must run the hook twice, never once with times=2. AddCounter 1*2 can step from 2 to 4 and skip the CounterIs 3 check.

Site (b): the reshuffle is in request_take_top (chance.rs:312-313, `if self.draw().is_empty() { move_all(Discard, Draw) }`), not in take_top. chance.rs also has move_all at :453 and :683, the outcome and resolve paths. Check whether these must not fire again.
