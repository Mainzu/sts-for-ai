### sts-rl-agent: a learned non-combat policy for Slay the Spire (2026)
- **Link:** https://huggingface.co/Jialeiv/sts-rl-agent (GitHub repo valiant-wjl/sts-rl-agent returned 404 on fetch) · **Venue:** Hugging Face model card · **Cited by:** n/a · **Read:** full text (model card)
- **Problem:** Learn the non-combat choices (map pathing, card rewards, shops, campfires, events) on the sts_lightspeed simulator. Combat stays with the simulator's built-in MCTS.
- **Method:** REINFORCE from scratch. A small MLP (about 100k params, hidden [128, 128]) scores each candidate; argmax picks the action. Input is a 412-dim game observation concatenated with a 368-dim candidate descriptor. Card candidates need a card-vocabulary file.
- **Assumes:** sts_lightspeed (C++, 412-dim NNInterface per the card). Ironclad, Ascension 0 only. Training data 15k games (main checkpoint) and an earlier 8k-game checkpoint. No compute or wall time given.
- **Claims:** On 50 fixed seeds, MCTS@50000: avg floor 42.5 and 14% win rate. Stock bot heuristics with random map pathing: 31.2 floors and 6%. MCTS@2000 with the same model: 38.5 floors and 4% wins. Six attempts to distill MCTS combat into feed-forward nets all underperformed; the card attributes this to MCTS using knowledge of future draws. Conclusion on the card: judgment-type decisions compress into small nets, planning-type ones do not.
- **Evaluation:** Single run, 50 fixed seeds, no confidence intervals. A0 Ironclad only. Defect A20 extension paused.
- **Code:** Model card says MIT license. Repo link 404 on fetch.
- **Fit:** partial. Directly relevant to our run layer (a candidate-scoring net over fixed features). Its negative result on distilling combat planning into a feed-forward net bears on our value-net-for-combat choice. It does not test unseen cards or enemies.

### AutoClad (GitHub, in progress)
- **Link:** https://github.com/benmuth/AutoClad · **Venue:** GitHub · **Cited by:** 2 stars · **Read:** full text (README page)
- **Problem:** Supervised imitation of a hand-written baseline (SimpleAgent) for Ironclad combat, aiming at Ascension 20 Ironclad eventually.
- **Method:** `data_parser.py` builds state feature vectors and action labels (which card was played). `main.py` trains a net by supervised learning, with early stopping. The model is exported to TorchScript for C++ inference. RL is listed as a later step.
- **Assumes:** Data generated by sts-lightspeed (`randomize_scenarios.py`). Scope so far: Jaw Worm encounters only. Feature encoding not described on the page.
- **Claims:** None quantitative. Status says "Currently focused on benchmarking different approaches"; Jaw Worm training and C++ inference are marked working.
- **Evaluation:** Example command generates 20 randomized scenarios. No win rate or floor results.
- **Code:** https://github.com/benmuth/AutoClad, LICENSE.md present (type not shown on page).
- **Fit:** partial. Confirms the "teacher then net, C++ inference" pattern in a combat setting, with no numbers. Only Jaw Worm, so no generalisation evidence.

### AscensionAI: Ironclad PPO agent, live game then sts_lightspeed (2025/26)
- **Link:** https://justinochan.github.io/AscensionAI/ (writeup PDF at /AscensionAI_Technical_Writeup.pdf was not readable: classifier error on fetch) · **Venue:** project page (writeup PDF) · **Cited by:** n/a · **Read:** abstract (project page only; the page is partial)
- **Problem:** A from-scratch Ironclad agent. First trained against the live game through mods, then moved to the headless simulator.
- **Method:** Behavior-cloning warm start from a heuristic, then PPO fine-tuning with parallel rollouts. Live game PPO reached avg floor 14.66 with boss win 38.1%. Reward, obs size and BC demo count are not on the page.
- **Assumes:** Live game about 90 games/hour. Simulator about 17k games/hour (stated as ~190x). Training on a self-healing GCP spot VM.
- **Claims:** Deployed mainline_v3: avg floor 26.1, 9 wins out of 150 seeds (6.0%). mainline_v2: avg floor 24.9, 7 wins (4.7%). Live PPO: avg floor 14.66, boss win 38.1%, 0 wins over ~21,700 games (200 eval games). Combat boss win with search: 75–88%, versus 44% for a learned feed-forward policy. The page says combat execution was the main bottleneck, not reward, capacity or deck-building. Ascension level not stated.
- **Evaluation:** 150 fixed seeds (v2, v3). 200 eval games (live).
- **Code:** none found (not checked).
- **Fit:** partial. Useful evidence that a learned feed-forward combat policy lost badly to search (44% vs 75–88%), which matters for our expectimax-plus-value-net design. Ascension not reported; no generalisation tests.

### Deep RL for a Slay the Spire deckbuilder (aiplaytesting project page, MiniSTS-like)
- **Link:** https://aiplaytesting.github.io/ai · **Venue:** project web page (custom deckbuilder modelled on StS, 32 cards, boss fight) · **Cited by:** n/a · **Read:** full text (page)
- **Problem:** Train an agent to win a small deckbuilder battle with an StS-like structure.
- **Method:** DQN, with later Monte Carlo return experiments. The state is a vector of player/boss HP, block, buffs, boss phase threshold, energy, and counts of hand, playable, draw and discard. Output is one Q-value per card in the deck (12 outputs for a 12-card deck), with action masking. The end-turn action was removed; the turn ends when nothing is playable.
- **Assumes:** Custom game, not StS. 10–12 card decks. One test deck in most experiments.
- **Claims:** Naive DQN ~ random-bot level. Three split models about 15% in an easy (100 HP boss) setting, vs 7–8% random. Realistic settings (240 HP boss, 75 HP player): about 0.5%, and 1–2% after fixes. Action masking: about 60%. Monte Carlo returns: about 80% on the same test deck ("the highest reported" per the page). Smaller net: about 5% drop. Unplayable-card avoidance: 1,000–2,000 games without masking, 200–300 with. Training time cut from 24–36 h to 6–8 h after shrinking the net from 5x512 to 128/64/32.
- **Evaluation:** Win rate vs random bot (5–8%). No held-out set or games-per-eval count given.
- **Code:** none found (not checked).
- **Fit:** partial. The one-Q-per-card output with masking is the closest published analogue to scoring cards by effect. It is not StS, and the numbers are not comparable across settings.

### Miles Oram: Slay the Spire ML project (C++ Ironclad recreation with deep RL)
- **Link:** https://milesoram.github.io/slay-the-spire-ml-project.html · **Venue:** personal project page (C++ recreation of all 4 acts, Ironclad only) · **Cited by:** n/a · **Read:** full text (page)
- **Problem:** A deep RL system that plays and wins full runs of StS at base difficulty.
- **Method:** Two-level. Micro (combat): Double DQN with MSE and Adam, 296 actions (play each unique card or its upgrade, or end turn; masked), curriculum of six stages, lower gamma for stability, ~18M params. Macro (map/run): feedforward net with Huber loss predicting expected end floor, ~9M params, fed by a separate net estimating per-fight HP loss.
- **Assumes:** Micro input 1,325 values: hand (max 10) per-card detail; deck, draw, discard, exhaust as per-card counts. Card, potion and enemy embeddings with size 80 (50 and 100 rejected). Slots shuffled during training as augmentation, disabled at simulation. Vocabulary 131 cards, each with an upgrade. Macro input 878 values (path re-evaluation plus one-hot of upcoming floors). Counts cannot capture temporary energy costs or stat changes.
- **Claims:** Beat the game over 100 times before training was stopped. Highest average end floor over 100 consecutive runs: 24.8, with 4 successful runs in that window. First-fight HP left: random 59.3 ± 7.1, author 73.6 ± 3.1, trained small DQN 72.1 ± 2.8. Compute and wall time not stated ("compute was limited").
- **Evaluation:** Micro: average end HP after each fight over large samples. Macro: average end floor. Card embeddings checked by normalised dot-product similarity.
- **Code:** none found (not checked).
- **Fit:** good on encoding. Per-card embeddings, count-based piles, slot-shuffle augmentation, and a micro/macro split are close to our design. Generalisation to unseen cards or enemies is not addressed. Wall time is not reported.

### Doron Singer, Part 2: Looking where the light is (DEV blog series)
- **Link:** https://dev.to/doronsinger/part-2-looking-where-the-light-is-12p5 · **Venue:** DEV Community blog · **Cited by:** n/a · **Read:** full text
- **Problem:** Network size, reward, and input/output encoding for a learned StS agent that aims at Ascension 20.
- **Method:** Behavioral cloning from spirecomm's AI on 500 recorded games, then RL with +1.0 per floor. Each card is 25 hand-picked features (cost, damage, block, poison, draws and so on), scaled to roughly 0–1. Hand and draw pile are mean-pooled.
- **Assumes:** Live game via spirecomm. Silent and Ironclad card sets. Some features are sparse (one card of 1261 has a unique effect); two of 25 card features had zero std.
- **Claims (version table):** v2 baseline: avg floor 12.4, boss reach 51%, 0 wins. v3 (deck multiplier x5): 14.7, boss reach "high", 0 wins. v4 (+combat bonus): boss reach 70%, 0 wins. v5 (+potion/relic/maxHP bonuses): 13.1, 60%, 0 wins. v8 (fixed card IDs): about 15, about 66%, 0 wins. A string-matching mismatch silently scored cards as worthless; fixing raised boss reach to about 66%.
- **Evaluation:** Live game runs; no fixed seed set reported.
- **Code:** none found.
- **Fit:** good for lessons. Mean-pooling destroys slot identity (the same failure as Part 4). Per-card feature vectors are close to our effect-primitive idea. Silent failures should fail loudly. No wins in any version.

### Doron Singer, Part 4: Slay the Cultist (DEV blog series)
- **Link:** https://dev.to/doronsinger/part-4-slay-the-cultist-9n7 · **Venue:** DEV Community blog · **Cited by:** n/a · **Read:** full text
- **Problem:** Beat the Cultist (the easiest early fight) losing as little HP as possible, as a damage-race problem.
- **Method:** Self-play PPO. Policy outputs a probability per possible play (including end turn) and a value prediction. Per-card hand scoring head added after mean-pooling was found to hide card identity.
- **Assumes:** Cultist only. 200,000 steps (about 14,000 fights). PPO: lr 3e-4, 1,024 steps per batch, minibatch 256, 10 epochs, gamma 0.99, GAE lambda 0.95, clip 0.2, entropy coefficient 0.15.
- **Claims:** Baseline 70% win after 200k steps, 30% losses. Per-card hand scoring: 100% win after 10k steps (the author later calls this misleading because of an energy-reset bug). End-of-fight HP about 47, then about 55 after reward changes, about 63 with an always-block heuristic. A latch bug corrupted PPO runs a third of the way in.
- **Evaluation:** Win rate and end HP vs Cultist.
- **Compute:** Not reported.
- **Code:** none found.
- **Fit:** partial. The hand-slot identity lesson is directly relevant. Single enemy, no generalisation. Latch bug and energy-reset bug are cautionary.

### mini-spire (Rob Pitkin, blog)
- **Link:** https://rhp.bearblog.dev/mini-spire/ · **Venue:** personal blog (C++ with Python bindings, Gymnasium-style API) · **Cited by:** n/a · **Read:** full text
- **Problem:** A fast RL env for StS, since gym-sts is slow and Miles Oram's C++ Ironclad lacks docs and a Gym API.
- **Method:** Flat 45-float count observation: one index per unique hand card (count), plus draw, discard and exhaust piles as counts. 7 discrete actions (hand slots, end turn), invalid ones masked. Reward +1 win, -1 loss, optional HP term on a win. ~15k-parameter maskable PPO (Stable-Baselines3).
- **Assumes:** Ironclad starter deck and upgrades vs Jaw Worm only. Vector size grows with unique cards (planned 2N + C).
- **Claims:** Raw env ~145k steps/s, one env, M1 MacBook Pro CPU. Training ~4,300 env steps/s. 1M timesteps in about 4 minutes. Random policy ~52% win. Trained agent ~90% win within ~50k steps; stopped losing by ~80k steps.
- **Evaluation:** Jaw Worm, single fight. No generalisation tests (other enemies, characters, multi-fight are future work).
- **Code:** link not captured in the fetch; not checked.
- **Fit:** partial. Good benchmark for env speed and maskable PPO. Count encoding drops slot identity. One enemy only.
